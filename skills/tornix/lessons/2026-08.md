# Lessons — 2026-08

## 2026-08-11 — Meeting rooms are `video_rooms`, NOT `chat_rooms`
Creating a row in `chat_rooms` does NOT show up in the Meetings tab — that table
is team chat. Meeting/video rooms live in `video_rooms` (Prisma `VideoRoom`,
`prisma/schema/meetings.prisma:196`). CLI: `tornix meetings room-create`.
Status: PROMOTED to SKILL.md (Meeting section).

## 2026-08-11 — `agile_task_slots` INSERT is blocked via data proxy
The table is NOT in `TABLES_WITH_ORG_ID`, so `isModelScopeProven` refuses
INSERTs for normal users (role `api_key`). The official pin API takes
`actorId` from the JWT only — no impersonation. Service keys (role `service`)
are exempt but none available. Workaround: none via API; pins must come from
the web UI or a service-key caller.
Status: ACTIVE (blocked).

## 2026-08-11 — `data select/update/delete` on `documents` needs `--filter "col=eq.val"`
The `--eq col=val` shorthand double-prefixes to `eq.eq.val` and silently
returns `[]` on the documents table. Use the raw PostgREST form.
Status: PROMOTED to SKILL.md (File upload section).

## 2026-08-12 — Downloading document content = `storage signed-url` + curl
`documents list/get` return metadata only (`document_path`). To fetch content:
`tornix api storage signed-url --bucket files --path "<document_path>" --download true --json`
→ signed S3 URL (1h) → curl. `document_path` is already `files/<project_id>/<uuid>.<ext>`.
Status: PROMOTED to SKILL.md (Reading/downloading documents section).

## 2026-08-12 — WBS tree = `gantt_wbs` table, tasks link via `wbs_id`
The Gantt renders a real WBS tree when `gantt_wbs` rows exist and tasks carry
`wbs_id` (frontend `gantt-adapter.service.ts` `transformWithWbsTree`). Sections
are ignored when a WBS tree exists. `ganttWbs` IS in `PROJECT_SCOPED_DELEGATES`
(direct) → INSERT allowed via data proxy. Empty branches are dropped.
Status: ACTIVE (WBS build in progress).

## 2026-08-12 — Skill must be multi-user: profiles + discovery, not hardcoded IDs
The skill was Karem-specific (user ids, team, default project hardcoded in
SKILL.md). For reuse across users: SKILL.md stays generic, per-user data lives
in `profiles/<user>.md`, bootstrap via `tornix auth whoami` +
`api organizations list` + `projects list` + `api projects members`.
Status: ACTIVE (migration in progress).

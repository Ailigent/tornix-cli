# Lessons — 2026-09

## 2026-09-22 — A meeting is a CALENDAR entry; `room-create` alone is the bug
Reported as «بقوله اعملي اجتماع، مش بيعمله في الكاليندر ولا بيعرف يدعو حد».
`tornix meetings room-create` writes one `video_rooms` row. The calendar reads
`calendar_events` — a different table — so the meeting was on nobody's calendar,
had no attendees, and fired no invitation. Nothing was broken; the persona was
telling the agent to write one table and read another.

A meeting is three things written together:
1. `video_rooms` + `metadata.scheduledStartDate` / `scheduledEndDate` /
   `calendarEventTitle` / `invitedParticipants` — without `scheduledStartDate`
   the Meetings tab renders a bare ad-hoc "quick room";
2. `calendar_events` (`title`, `start_date`, `end_date`, `participants[]`,
   `meeting_link`, `video_room_id`, `user_id`) — the ONLY table the calendar reads;
3. nothing — the data proxy notifies every `participants[]` entry with an `id`,
   on INSERT *and* UPDATE.

Use `tornix calendar create|list|invite|uninvite|update|delete|members`, and the
`meeting` skill for the edge cases.
Status: PROMOTED to SKILL.md (Meetings section) + the `meeting` skill.

## 2026-09-22 — Write calendar invites through the DATA PROXY, not `/calendar/events/:id`
`PATCH /api/v1/calendar/events/{id}` is a direct Prisma update with no data-proxy
event hook, so adding an attendee through it is SILENT. `handleCalendarEventDataProxy`
only runs off `/api/v1/data/calendar_events`. Every mutating calendar command goes
through the proxy for exactly that reason.
Status: ACTIVE (design constraint).

## 2026-09-22 — `calendar_events` is creator-scoped; `{"count": 0}` is not success
The table has no `organization_id`, so the proxy scopes it by `user_id` (the
CREATOR). A filtered UPDATE/DELETE against somebody else's meeting matches no row
and returns `{"count": 0}` rather than an error — which reads as success. Also:
never answer "what meetings do I have" with `tornix data select calendar_events`;
it silently omits every meeting a colleague booked the user into. Use
`tornix calendar list` (→ `GET /calendar/my-events`), which returns both.
Status: ACTIVE.

## 2026-09-22 — `tornix api meetings create` does NOT schedule a meeting
It creates a `meeting_session` — a recording/minutes record whose DTO has no
title, no date and no attendees. `tornix meetings list` is likewise HISTORY
(recorded sessions), org-wide, not the caller's schedule.
Status: PROMOTED to SKILL.md.
